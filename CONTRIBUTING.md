# Contributing to Alchemy IDE

First off, thanks for taking the time to contribute! 🎉

Alchemy IDE is a native code editor and file manager for Android, and contributions of all kinds are welcome - code, bug reports, documentation, or feature ideas.

## Code of Conduct

This project follows a [Code of Conduct](CODE_OF_CONDUCT.md). By participating, you're expected to uphold it.

## AI Contribution Policy

Generative AI may be used for contributions as long as the contributor is fully aware of the content generated, takes full responsibility for it and ensured that no copyrighted content from third parties is included.

We welcome contributions assisted by AI tools, provided they follow these rules:

1. **Human-responsibility:** You are 100% responsible for the code you submit. You must understand every line of the AI-generated output.
2. **No "Dry" Submissions:** Do not submit AI-generated code that you have not locally compiled, tested, and verified.
3. **Disclosure:** If a significant portion of your PR (e.g., a new module or complex function) was generated by AI, please state so in the PR description.
4. **Licensing Compliance:** Ensure that the AI tool you use does not violate our project's [LICENSE](https://github.com/SibtainOcn/alchemy-IDE/blob/main/LICENSE). You must ensure you have the right to contribute the generated code.
5. **Succinctness:** AI tends to be verbose. Please prune any unnecessary comments or boilerplate generated by the tool before submitting.

**Failure to follow these guidelines may result in your Pull Request being closed without review.**

## Before You Start

- Check [existing issues](https://github.com/SibtainOcn/alchemy-IDE/issues) first to avoid duplicates.
- For anything non-trivial (new features, large refactors), open an issue to discuss before writing code - saves everyone time if the approach needs adjusting.

## Development Setup

### Prerequisites
- Android Studio (latest stable recommended)
- Android SDK, minimum API 24 (Android 7.0)
- JDK 17+
- (Optional) Termux installed on a test device - needed if you're testing the "Run Code" feature


## Code Style

- Follow standard Kotlin/Java conventions
- Comment non-obvious logic, especially around file I/O and Termux integration
- Match the existing formatting style in whatever file you're editing

## Submitting a Pull Request

1. Create a new branch from `main`
2. Make your changes, following the guidelines above
3. Test thoroughly on-device
4. Push to your fork and open a PR against `main`
5. Fill in what the change does, how you tested it, and screenshots or recordings for UI changes
6. Be responsive to review feedback

### PR Checklist
- [ ] Code builds without errors or warnings
- [ ] All test checks passed
- [ ] Tested on a real device or emulator (API 24+)
- [ ] Follows existing code style
- [ ] Related issue linked (if applicable)

## Reporting Bugs

Use the **Bug Report** template when opening an issue, and include:
- Alchemy IDE version
- Android version and device model
- Steps to reproduce
- Expected vs. actual behavior
- Screenshots or logs attached if available

## Suggesting Features

Use the **Feature Request** template. Explain the problem you're trying to solve, not just the solution.
